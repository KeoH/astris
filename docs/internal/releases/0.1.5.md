# Astris 0.1.5

Release date: 2026-03-01

### Highlights

- Consolidates theme-system improvements and maintenance updates under a single 0.1.5 release.

### What's changed

#### Added
- Added internal release notes for `0.1.5` at `docs/internal/releases/0.1.5.md`.
- Added `Theme` API in `astris.theme` with configurable tokens (`colors`, `spacing`, `scales`), component defaults, and extra metadata.
- Added render-scoped theme activation so components can resolve defaults at render time.
- Added test coverage for theme model behavior and component/default merge semantics.
- Added external stylesheet registration to `astris.theme.Theme` (`stylesheets` + `add_stylesheet(...)`) with href validation.

#### Changed
- Updated package version metadata to `0.1.5` in project metadata and runtime exports.
- Updated changelog with the `0.1.5` release entry.
- Updated `Astris` to accept `theme=Theme(...)` and inject theme CSS variables into rendered output.
- Updated rendering to set `data-theme` on `<html>` and `color-scheme` from theme mode.
- Updated `Element` to merge theme defaults with explicit props preserving explicit-prop precedence.
- Updated `Column` and `Row` defaults to include `gap: var(--space-md, 1rem)`.
- Updated public exports and user docs to include theme usage.
- Expanded public docs with a detailed class-generation workflow using `Style` and `GlobalStyleSheet`.
- Updated head asset injection order to load theme external stylesheets before generated theme CSS and app-level head links.
- Updated head link rendering to deduplicate repeated stylesheet hrefs across theme and app registrations.

#### Fixed
- Aligned release metadata across repository files to keep packaging and release automation consistent.
- Ensured theme changes on `app.theme` are reflected in subsequent renders/builds without redecorating routes.

### Why this matters

- Ensures a clean and consistent release state before publishing artifacts.
- Reduces packaging/release friction caused by mismatched version metadata.
- Enables consistent design tokens across applications while keeping per-component override flexibility.
- Preserves current route-registration semantics and static build behavior.
